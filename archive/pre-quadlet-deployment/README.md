# `archive/pre-quadlet-deployment/` — the openclaw compose-era deployment layer

**Reference material. Not installed, not executed, not tested, and not the deployment path of this
repository.** Deploy this repository with `scripts/install.sh` (Quadlet + systemd). Everything
under `tree/` describes what came *before* that, and is kept only so the work is not lost.

本目錄為**歷史參考資料**，不是本倉庫的部署路徑，請勿執行；實際部署請用 `scripts/install.sh`。

`tree/` is a byte-identical copy of the host directory, minus the files listed under
*What was excluded* below. No preserved file was edited.

## Where it came from / 來源

Host `woowtechopenclaw`, directory `~/Woow_podman_odoo`.

That directory was assumed to be a clone of this repository. It is not: it has **no `.git` at
all** — no remote, no history, no bundle — and the SHA recorded in its `.deployed-commit`
(`725a7f3a0441d07092ba2f5960dacb1061b15a8a`, preserved in `tree/`) does not resolve in this
repository or anywhere else in the WOOWTECH organisation. A file-by-file comparison against `main`
and an org-wide code search found this material in no git repository anywhere. It was live code:
`odoo18.service` on that host ran `tree/scripts/service.sh start` on every start, and
`tree/scripts/odoo-healthcheck.py` was bind-mounted into the running web container.

Extracted from the local backup
`~/.local/share/woow-openclaw-deployment-backup/20260913-234957/deployment-layer.tgz`
(sha256 `13b07d18c3f511e602f63ba4bcff17705cca5bcdd69ef063cf136ac0bf87778f`, captured 2026-09-13).
Nothing was read from, or changed on, the host to produce this directory.

## What it deployed / 部署內容

Odoo 18 as a `podman-compose` project named `odoo18`: `odoo18-db`
(`pgvector/pgvector:0.8.0-pg16`, digest-pinned) and `odoo18-web` (`odoo:18.0`, digest-pinned) on
the `odoo18-network` bridge, with the web UI fixed to `127.0.0.1:18069` and no published database
port. `odoo18.service` (oneshot, `TimeoutStartSec=600`) drove `scripts/service.sh`; an
`odoo18-health.service` + `.timer` pair polled the instance.

What is worth keeping around the compose file: the rendered-config model
(`tree/scripts/render-config.sh` renders `config/odoo.conf.template` into `.runtime/` and generates
the admin and database passwords, so no credential is ever a repository file); a stack/owner label
model (`io.woowtech.stack`, `io.woowtech.owner`) that let deploy, backup, restore and remove refuse
to touch another owner's resources; a backup-archive validator that rejects path traversal, absolute
paths, symlinks and device nodes (`tree/scripts/validate-backup.py`); a remote acceptance prober
(`tree/scripts/remote-probe.py`); and a **10-file pytest suite of about 1 700 lines** covering
deploy, remove, systemd unit rendering, backup/restore, runtime config and the live gates.

that check is about the live deployment path.

## What looks reusable / 可再利用之處

This tree carries **no captured podman output**: `tree/tests/fixtures/` contains only a README
saying that archives are generated in temporary directories and no binary fixture is tracked. The
reusable material here is therefore test *logic*, not test doubles:

* `tree/tests/test_backup_restore.py` (23 KB) builds malicious tar archives — path traversal,
  absolute members, symlinks, device nodes, oversized members — in a temporary directory and asserts
  the validator rejects each. The current `tests/test_backup_validator.py` is the descendant of
  this and already carries the idea; the archived version has cases the current one does not, and is
  worth diffing before the next change to `scripts/validate-backup.py`.
* `tree/tests/test_systemd.py` and `test_runtime_config.py` assert on rendered unit and config text
  rather than on a running system — the same offline-rendering discipline `tests/dryrun.sh` now uses.
* `tree/scripts/remote-probe.py` is a self-contained acceptance prober with no dependencies; there
  is no equivalent in the current tests.

**Assessment: nothing here should be wired into the current tests as-is**, because the current
suite tests a Quadlet deployment and these test a compose one. The one concrete follow-up is the
malicious-archive case list, which is deployment-independent.
**Deliberately not done in this change** — preservation first.
